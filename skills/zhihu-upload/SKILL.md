# Zhihu articles and videos

Use the repository's `sau zhihu` command; do not write a separate web upload flow.

## Overview

| Function | Command entry | Notes |
| --- | --- | --- |
| Login | `sau zhihu login --account <name>` | Save the local session for the given account |
| Account check | `sau zhihu check --account <name>` | Check whether the session matches the current account |
| Article publishing | `sau zhihu upload-article ...` | HTML/Markdown/TXT source; images keep their positions in the source |
| Video publishing | `sau zhihu upload-video ...` | A single video, title, description, category and content declaration |
| Post check | `sau zhihu verify --account <name> --result <json>` | Open the original post link in the result file and check the title |

Metadata conventions: articles use `title + content-file`, and videos use `title + desc + originality + category + video-mark`. `--account` is a local session alias and does not have to match the Zhihu nickname.

## Login

```powershell
sau zhihu login --account creator
sau zhihu check --account creator
```

Enter the account password and verification code in the login window. The session file is stored locally and is not committed to the repository.

## Article

The title is at most 100 characters. The body is UTF-8 HTML, Markdown or TXT; for Markdown, run `sau article setup` first on first use.

Put images at the matching paragraphs in the source; relative paths are resolved from the source directory:

```markdown
Body of the first paragraph.

![illustration](images/1.png)

Body of the second paragraph.
```

```powershell
sau zhihu upload-article --account creator --title "文章标题" --content-file "文章.md"
```

Before submitting, the text, image order, basic formatting and links are checked. If the editor restores a non-empty draft, the command stops so that existing content is not overwritten. Custom theme CSS, manual covers, column inclusion, Zhishi tasks and document import are not supported yet.

## Video

The file must be larger than 100KB (102400 bytes), at most 20GB and at most 4 hours long. The title is 5–50 characters and the description is at most 300 characters; the cover generated by the platform is used by default.

```powershell
sau zhihu upload-video --account creator --file "视频.mp4" --title "视频标题示例" --desc "视频简介" --originality original --category "教育" --video-mark "含 AI 生成内容"
```

- `--originality`: `original` or `reprint`.
- `--category`: see `sau zhihu upload-video --help` for the category options. If omitted, a live menu is shown and you choose by number.
- `--video-mark`: `内容无需标注` (no label needed), `含 AI 生成内容` (contains AI-generated content), `含虚构演绎内容` (contains fictional dramatization), `内容含营销信息` (contains marketing information), `内容为转载` (content is a reprint), `个人观点仅供参考` (personal opinion, for reference only). The declaration must match the content.

Non-interactive calls should specify the category and the declaration. The program still checks the live menu before submitting. To only get the options on the current page, use:

```powershell
sau zhihu upload-video --account creator --file "视频.mp4" --title "视频标题示例" --originality original --show-options
```

The options are written to `options.category` and `options.video_mark` in the result JSON. Automatic topic selection, custom covers, columns and content sources are not supported yet.

## Submission and results

Both articles and videos accept `--prepare-only`, which ends after filling in and checking the form. Both `--prepare-only` and `--show-options` may leave a remote draft.

`published` means the platform confirmed publication, and the detail link is written to `url` in the result file; a video address can be `/pin/<post-ID>`. If reading the details fails, `published` and `error` are kept; check the original post in the creator center and do not resend. `prepared` does not mean the post was published. For `submission_unknown`, also check the original post by title and submission time first. When a URL is already available, you can run:

```powershell
sau zhihu verify --account creator --result "本次结果.json"
```

`--schedule "YYYY-MM-DD HH:MM"` is an experimental option. It uses Beijing time and is limited to between 30 minutes and 48 hours from now; the full scheduling flow is not yet guaranteed to work.
